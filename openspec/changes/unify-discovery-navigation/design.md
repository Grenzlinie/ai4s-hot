## Context

见proposal.md。只读检查确认site/static/app.js的matches把sort=zotero及sort=alpha当作筛选条件；channel混用groups与type；来源为单值select。公开快照2026-10-09T06:45Z包含110个去重条目、53个主题、14个来源声明，含零结果来源。现有topic-explorer契约仍须保留。

## Goals / Non-Goals

**Goals:** 用户在同一列表中持续阅读，改变来源或排序不丢研究上下文；细主题仍可追溯。

**Non-Goals:** 本次不重训分类、不引入账号或远端兴趣画像，不改Zotero目录；交互预览不代表已部署，也不替代正式URL/纠错验收。

## Decisions

### 1. 信息架构

主导航只表达综合推荐/最新/收藏。访客界面统一使用“研究主题”“研究推荐”，不提个人Zotero或目录复用过程；后端来源ID与算法技术记录保持真实且兼容。左栏四维研究目录保留，去掉展示名数字前缀，完整原路径留在详情。中间按领域（材料/化学/生命科学/通用AI）与类型（论文/研究报告/模型发布/工程与工具/机构动态）独立筛选。来源常用按钮+所有来源搜索面板，多选OR；同维主题OR、跨维AND规则不变。

不采用另一组“科研Agent/前沿模型/论文”大频道，因为它仍将主题与类型混在一层。未来科研Agent快捷入口只能是显式可见的主题条件组合，不是隐式来源集合。

### 2. 视觉与布局

采用紧凑研究简报而非大面积营销hero。左栏220px、内容区可伸缩、最大1280px；标题32px、条目20px、摘要13px。纸白背景、深绿正文与选中态、暖棕类型提示，强视觉元素为顶部阅读方式下划线。卡片采用连续分隔线，避免重复盒子。领域/类型为紧凑按钮，来源为圆角胶囊；手机常用来源横向滚动，所有来源打开原生dialog，主题目录也进入dialog。支持390px、键盘、focus-visible、reduced-motion。

这种布局比“只美化下拉”更重要：来源点击、卡片标签、收藏及推荐方式统一修改同一state，而不是导航到彼此隔离的页面。

### 3. 统一候选与推荐

先按查询、日期、主题、领域、类型、来源及收藏/未读得到唯一ID候选，再排序。最新按published_at，缺失时first_seen，使用ID打破同分，并标“收录”。

初始综合方案使用公开快照的三个排名：时间、有限Zotero分数降序、有限alpha_rank升序。RRF score=sum(1/(60+rank))，只对拥有信号的列表贡献；不直接相加量纲不同的原始分数。对综合序列作多样性打散：连续三条同类型后优先取下一最高分不同类型条目；连续两条存在共同来源时优先取不含该共同来源的条目。先寻找同时满足两者的条目，再依次尝试类型约束、来源约束，无法满足则继续原序，不丢条目。所有候选最终均可分页读取。

这是可调整的起始策略，不能声称已改善推荐质量。来源贡献偏差会影响靠前位置；保持“最新”作为透明替代，卡片显示研究推荐/alphaXiv排名/发布时间。多来源条目按共同来源集合处理，避免首来源不同但都含Zotero的论文连续占满列表。类型配比与排序权重仍是初始设计。

### 4. 状态和数据边界

复用公开taxonomy/topic_ids/domain_facets/content_kind/source_ids和sources元数据，零内容来源仍显示。不新增私有配置或第三方前端API。正式版沿用ai4s-read/ai4s-saved/corrections键；预览使用独立ai4s-preview-saved，避免影响真实阅读状态。正式state与派生candidate/sort分离，计数忽略本轴条件而保留其他轴；最终计数按ID并集。

### 5. 兼容与证据

旧source迁移至sources数组；旧channel按原表达式作为显式“旧频道条件”，而不是近似映射为错误学科。旧zotero/alpha排序保留显式“仅有该信号”兼容条件并说明，清除后进入新统一排序。主题稳定ID/alias/retired逻辑不改。准确率未量化说明放在主题区，不以全站版本横幅占据阅读空间。

## Risks / Trade-offs

- [领域覆盖不全] → 无领域条目保留全部列表，不用品牌推断补齐。
- [RRF更偏向有推荐信号的论文] → 多来源打散、全部可分页、最新入口；质量收益留待真实评估。
- [筛选层多] → 收紧hero和控件高度；手机将细目录移入面板，已选条件始终可清除。
- [精细目录被边缘化] → 保留桌面常驻侧栏、手机独立按钮、卡片主题直接点击及完整路径详情。

## Migration Plan

1. 已确认的独立HTML预览使用公开快照；用户于2026-10-09明确授权替换线上页面。
2. 实施将state/匹配/排序分离，实现展示与兼容，不修改分类算法。
3. 本地功能与独立浏览器验收，覆盖来源OR/去重、候选守恒、同分稳定、缺日期、空态、旧链接、localStorage、纠错、退役主题及390/1440布局。
4. 生产发布前记录Git主分支与site-data归档SHA。使用既有GitHub Actions/Pages部署，核验部署HEAD及公开页面。
5. 回滚静态资源至记录的前版；公开归档和本机状态键保持兼容，不丢收藏。
