## Why

当前分类将材料体系、AI 方法、评测及公司新闻放在一个 TF-IDF 竞争池，出现明确的研究主题漏分和组织新闻错分；目录 ID 随名称变化、浏览计数与筛选不一致，也使分类难以持续维护。应先建立可解释、可纠正、可验收的分类体系，再追求更多自动标签。

## What Changes

- 保留 Zotero 四个研究主目录与层级，引入稳定公共 ID、重命名迁移和经过选择的目录发布策略。
- 为主题增加定义、同义词、纳入/排除规则；材料对象、AI 方法、数据评测、科研软件分别匹配，不共用一个全局前三名配额。
- 在网站增加独立的内容性质/通用领域标签，覆盖模型发布、工程更新、生命科学及组织动态，不擅自修改 Zotero 库。
- 将全部“待分类”区分为待处理、低置信度、证据不足、研究目录外和目录缺口；输出理由、版本和纠错状态。
- 本地多语言语义候选与词语证据相结合；先校准拒判、细分类与多标签，再按实测决定是否启用语义后端。
- 主题搜索、独立展开/选择控件、筛选范围内计数、移动端目录抽屉、可分享 URL 和本地纠错导出。
- 建立冻结人工标签集、强制回归案例、离线质量报告、影子运行及回滚。
- **BREAKING**：新增 v2 主题身份与分类记录，但迁移保留旧主题别名；前端至少兼容上一版 index schema。

## Capabilities

### New Capabilities
- `topic-curation`: 类别定义、人工覆盖、纠错导出/导入、优先级和审计。
- `classification-evaluation`: 冻结标签、无泄漏切分、分层指标、运行预算和发布门槛。

### Modified Capabilities
- `taxonomy-sync`: 稳定身份、目录发布策略、变更事件、别名和迁移。
- `topic-assignment`: 分维度多标签、领域识别、证据不足、可解释性与完整缓存版本。
- `topic-explorer`: 范围计数、可访问的树形交互、状态 URL、手机端和纠错入口。

## Impact

计划修改 `site/site_topics.py`、`collect.py`、前端和配置同步工具，增加分类 catalog、overrides、评估工具与验收 fixtures。继续使用 GitHub Actions/Pages，不新增服务端数据库，不发送邮件，不把私有 Zotero 资料交给外部模型。现有 arXiv 个性化排序任务的耗时问题另列运行依赖，不把其成功与否混同为主题质量。

本轮交付仅为设计与项目管理文件，不实施上述业务行为；详细证据见 `audit.md`，设计、验收与任务见同目录文件。
